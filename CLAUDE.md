# CLAUDE.md — интернет-магазин «ОРБИТА»

Руководство по проекту в том виде, в каком он **реально устроен**. Отвечает на вопросы «что это», «из каких кусков состоит», «где что лежит», «какие контракты нельзя ломать» и «как проверить, что всё работает».

**Приоритеты:** исправность → удобство → визуальное качество → насыщенность. Не добавляй крупные функции, пока ядро (каталог, корзина, суммы) не зелёное.

---

## 0. Сводка

**Что это.** Учебный интернет-магазин вымышленного бренда «ОРБИТА / снабжение за пределами Земли». Покупатель собирает комплект для экспедиции на Луну, Марс или орбитальную станцию. Бренд, товары, цифры и экспедиция «Орбита-1» вымышлены; оплаты и сбора личных данных нет.

**Стек.** Чистые HTML, CSS и ES-модули. **Сборщика нет:** папка `site/` и есть готовая статическая сборка. Backend, БД, CDN, внешние шрифты и аналитики нет. Тесты ядра — `node:test`, API — `pytest`; автоматических браузерных тестов нет. `main.py` из шаблона: локальный сервер и упаковка в ZIP.

**Главная идея архитектуры.** `core/` ничего не знает об интерфейсе: чистые функции без DOM. `ui/` только вызывает `core/` и рисует результат. Поэтому корзина считает правильно, даже если декор сломался, и расчёты проверяются без браузера.

## 1. Что строим (требования)

### Концепция и путь пользователя
Витрина → выбор экспедиции → рекомендации → корзина → промокод → «Паспорт экспедиции».
16 товаров в 4 категориях (Питание, Оборудование, Быт, Сувениры). У каждого: название, цена в ₽, SVG-изображение, короткое описание, 3–4 характеристики, остаток.

### Визуальный стиль
- Графитовый фон, тёплый светлый текст, сигнальный оранжевый. Каталог и «О бренде» — на светлой бумажной поверхности для читаемости.
- Крупные заголовки, моноширинные технические подписи, тонкие линии, номера изделий (`ОР-101…`).
- Текстовый логотип «ОРБИТА» (буква «О» — орбитальное кольцо), единый набор линейных иконок (`currentColor`, штрих 1,6).
- Анимации короткие (≤ 0,4 с), всё отключается при `prefers-reduced-motion`. Заставок и загрузочных индикаторов нет.
- Первый экран: бренд, одно ясное предложение, чертёж модуля ОР-1 на орбите Луны, кнопки «Открыть каталог» и «Собрать экспедицию».

### Обязательное ядро (работает независимо от декора)
Каталог с названиями, ценами и кнопками добавления; добавление и удаление в корзине; правильный пересчёт суммы; пустая корзина показывает 0 ₽.

### Каталог
Категории и «Все товары»; поиск по названию; сортировка по популярности и цене; всё работает совместно; счётчик найденного; «Ничего не найдено» со сбросом; быстрый просмотр; избранное с сохранением; кнопка добавления показывает результат («Добавлено»).

### Корзина
Открывается из шапки; счётчик = число единиц; строка с изображением, ценой, количеством и суммой; «+» / «−», удаление, очистка; количество в пределах 1…остаток; «Отменить» после удаления (8 с); пустое состояние с переходом в каталог; итог «Товары / Скидка / К оплате»; сохранение между сессиями; промокод `ORBIT10` (−10% на товары; неверный код — сообщение, повтор скидку не увеличивает, код можно убрать).

### «Собери экспедицию»
Три шага (направление, срок 3/7/14 дней, приоритет) → набор из реальных товаров с пояснением «зачем», стоимость и масса, исключение позиций, «Добавить набор в корзину» с учётом уже выбранного и остатков, понятное объяснение частичного результата, возврат назад с сохранением выбора, «Паспорт экспедиции» (PNG, SVG, печать).

### Доступность
Семантическая разметка, подписи полей, видимый фокус, диалоги на `<dialog>` (Escape, ловушка фокуса, возврат фокуса на кнопку-открыватель), озвучивание уведомлений через `aria-live`, информация не только цветом, 44 px под кнопки.

### Хранение
Ключи localStorage с номером команды: `teamXX:cart:v1`, `teamXX:favorites:v1` (плюс служебный `teamXX:expedition:v1`). Номер команды — одна настройка в `site/js/config.js`; пока неизвестен — **`team00`** (указано в README). Повреждённое, устаревшее и недоступное хранилище не ломают сайт.

## 3. Контракты (не менять без согласования)

### 3.1 `config.js`
```js
TEAM_ID = "team00"
STORAGE_KEYS = { cart, favorites, expedition }       // `${TEAM_ID}:cart:v1` и т. д.
PROMO_CODES  = { ORBIT10: { percent: 10, label: "−10% на товары" } }
UNDO_MS = 8000
```

### 3.2 Схема товара (`data/products.js`)
```js
{ id: "mango-cubes",            // латиница, kebab-case, уникальный
  sku: "ОР-101",
  category: "food",             // "food" | "gear" | "home" | "gifts"
  name, price,                  // price — целые рубли
  mass,                         // граммы
  stock,                        // остаток, целое ≥ 0
  popularity,                   // для сортировки
  image: "./assets/products/mango-cubes.svg",
  short, description,
  specs: [["Состав", "манго 100%"], ...] }   // 3–4 пары [название, значение]
```
В каталоге есть товар с остатком 3 (`meteor-kit`) и один с остатком 0 (`station-model`) — на них проверяются лимиты и недоступное состояние.

### 3.3 API ядра
Состояние корзины: `{ items: { [id]: qty }, promo: null | "ORBIT10" }`. Все функции иммутабельны. `catalog` — `Map<id, product>` (`indexCatalog(products)`).

**`cart.js`**
```js
addItem(state, catalog, id, qty=1)    → { state, added, reason }   // reason: "ok" | "stock" | "unknown" | "invalid"
setQty(state, catalog, id, qty)       → state     // зажимает в 1…stock; для удаления есть removeItem
removeItem(state, id)                 → state
clearCart(state)                      → state     // очищает позиции; промокод остаётся
reinstate(state, catalog, entries)    → state     // «Отменить»: возвращает [{id, qty}], не затирая остальное
addMany(state, catalog, [{id, qty}])  → { state, results: [{id, requested, added, inCart}], requested, added, complete }
applyPromo(state, rawCode)            → { state, ok, already?, message }
removePromo(state)                    → state
summarize(state, catalog)             → { lines, count, subtotal, discount, total, promo, mass }
```
**Все суммы в интерфейсе берутся только из `summarize()`.**

**`promo.js`:** `calcDiscount(subtotal, percent) = Math.floor((subtotal*percent + 50) / 100)` — единственное правило округления (до целого рубля, половина вверх, без float). Код нечувствителен к регистру и пробелам.

**`catalog.js`:** `filterProducts(products, { query, category, sort, favoritesOnly }, favoritesSet)`; `sort`: `"popular" | "price-asc" | "price-desc"`. Поиск — по названию, без учёта регистра и «ё».

**`expedition.js`**
```js
recommend({ dest, days, priority }, products) → [{ id, product, qty, why }]
kitTotals(items, excludedSet)                 → { active, count, positions, cost, mass }
describeExpedition(sel)                       → { dest, duration, priority, title, text }
passportNumber(sel, items)                    → "ОР-МАР-7И-0229"   // детерминированный
```

**`store.js`:** `createStore({ products, storage })` → `getCart, summary, qty, left, add, addMany, setQty, remove, clear, reinstate, applyPromo, removePromo, favorites, isFavorite, toggleFavorite, subscribe, recovered, persistent`. Подписчик получает `"cart"` или `"favorites"`.

**`storage.js`:** `createStorage(backend?)` → `{ persistent, read(key) → {status, value}, write, remove }`. Статусы: `ok | missing | corrupt`. Если `localStorage` недоступен или бросает — данные живут в памяти сессии.

### 3.4 Алгоритм подбора (`core/expedition.js` + `data/expedition.js`)
Для каждого товара в `EXPEDITION_META[id]`: `fit` (пригодность к Луне/Марсу/станции, 0–3), `prio` (комфорт/исследования/лёгкий багаж, 0–3), `perDays` (как часто нужна новая единица расходника), `why` (причина по направлению).

1. `score = fit[dest]*2 + prio[priority]*2 − massPenalty`; для «лёгкого багажа» `massPenalty = масса/200`.
2. Только товары в наличии и со `score > 0`; сортировка по score, затем по популярности.
3. Размер набора: 5 / 6 / 7 позиций для 3 / 7 / 14 дней, на одну меньше при «лёгком багаже».
4. В набор всегда входит питание.
5. Количество: расходники `ceil(days / perDays)`, остальные 1; не больше остатка.

Инвариант (проверяется тестом): все 27 комбинаций дают **разные** наборы.

### 3.5 Правила вокруг остатков
- В корзину нельзя положить больше `stock` — ни кнопкой, ни «+», ни набором.
- `addMany` учитывает уже лежащее: если остаток уже занят, добавляется 0 и в ответе `added < requested`.
- Интерфейс обязан объяснить частичный результат словами по каждой недобранной позиции.

## 4. Пакеты работ

Формат: **цель → что сделано → файлы → приёмка → зависимости**. Статус каждого — по фактическому состоянию репозитория.

### WP0 — Каркас и конфигурация
**Цель:** собираемый статический проект с единственной точкой настройки номера команды.
**Сделано:** структура `site/`, `config.js`, `package.json` (`"type": "module"`), `.gitignore`; `main.py` использует стандартную библиотеку (добавлена совместимость с Python 3.9 для `is_junction`).
**Приёмка:** `python3 main.py` отдаёт сайт; `python3 main.py --pack` создаёт `shop.zip` с `index.html` в корне; относительные пути; нет внешних URL.
**Зависимости:** нет.

### WP1 — Ядро расчётов, состояние, хранение
**Цель:** вся логика, от которой зависит «исправность», — проверена тестами.
**Файлы:** `site/js/core/*`, `tests/unit/cart.test.mjs`, `storage.test.mjs`.
**Сделано:** контракты раздела 3.3; нормализация данных из хранилища (`sanitize.js`: неизвестные id, нецелые и отрицательные количества, дубли, превышение остатка, чужой промокод, неверная версия); «Отменить» через `reinstate`.
**Приёмка:**
- 100 + 200 = 300; удаление по одному → 200 → 0, пусто.
- ORBIT10: 300 → 270; повтор → 270 (`already`); регистр и пробелы; неверный код не меняет сумму.
- Количество зажимается в 1…остаток; лимит остатка для `addItem` и `addMany`.
- Правило округления скидки на границах (5→1, 4→0, 15→2).
- Битый JSON, не тот формат, мусорные строки, бросающий `localStorage`, переполнение при записи — состояние не падает.
**Зависимости:** WP0.

### WP2 — Данные: каталог и подбор
**Цель:** живой правдоподобный ассортимент и правила подбора.
**Файлы:** `data/products.js`, `data/expedition.js`, `data/info.js`, `tests/unit/catalog.test.mjs`.
**Сделано:** 16 товаров, 4 категории, у каждого ≥ 3 характеристик; метаданные подбора и причины для **каждого** товара и направления; тексты окон «Доставка», «Возврат», «Контакты», «Об учебном проекте».
**Приёмка (тест):** уникальные `id`, целые цены и остатки, категории из списка, файл изображения существует, для каждого товара есть метаданные; 27 комбинаций подбора дают разные наборы, в каждом есть еда, количество ≤ остатка, у каждой позиции есть пояснение.
**Зависимости:** WP0.

### WP3 — Иллюстрации товаров
**Цель:** серия изображений, выглядящая как одна фотосессия.
**Файлы:** `tools/gen-images.mjs` → `site/assets/products/*.svg`, `site/assets/favicon.svg`.
**Сделано:** 16 SVG в едином стиле (светлая подложка, графитовый контур 3 px, оранжевый акцент, метки-перекрестия по углам, тень-эллипс). Запуск: `npm run images`. Скрипт защищён от дублирующихся атрибутов; все файлы проверены на well-formed XML.
**Приёмка:** каждому `id` соответствует файл; ни одного битого изображения в браузере (проверялось вручную); внешних ссылок нет.
**Зависимости:** WP2 (список `id`).

### WP4 — Дизайн-система и страница
**Цель:** единый визуальный язык и законченная страница вокруг каталога.
**Файлы:** `site/index.html`, `site/styles.css`.
**Сделано:** токены цвета и шрифтов в `:root`; системные шрифтовые стеки (без файлов шрифтов); спрайт иконок; логотип; чертёж модуля ОР-1 (SVG) с орбитальной точкой на CSS `offset-path`; шапка (липкая, на мобильном вторая строка навигации); блок «О бренде» с фактами экспедиции «Орбита-1»; подвал с навигацией и отметкой об учебном проекте; состояния hover/active/focus/disabled; `prefers-reduced-motion`.
**Приёмка:** первый экран на 1440×900 показывает бренд, предложение, объект и обе кнопки; горизонтальной прокрутки нет на 390 px; контраст текста не ниже AA (оценено на глаз).
**Зависимости:** WP0, WP3.

### WP5 — Каталог, быстрый просмотр, диалоги, уведомления
**Цель:** рабочая витрина.
**Файлы:** `ui/catalogView.js`, `ui/quickView.js`, `ui/dialogs.js`, `ui/toast.js`, `ui/dom.js`.
**Сделано:**
- Карточки с номером изделия, остатком, избранным и кнопкой «В корзину» (состояния: «Добавлено», «Весь остаток в корзине», «Нет в наличии»). Первая карточка в состоянии по умолчанию — крупная.
- Поиск, категории с счётчиками, сортировка, «Только избранное», счётчик «Найдено: N из M» (`role=status`), пустое состояние со сбросом.
- Быстрый просмотр: изображение, описание, характеристики, остаток, избранное, добавление.
- `dialogs.js`: `<dialog>` + Escape, закрытие по подложке, ловушка Tab, возврат фокуса на кнопку-открыватель, блокировка прокрутки.
- `toast.js`: тост рисуется **внутри открытого диалога**, иначе в углу страницы, поэтому не перекрывает кнопки; не исчезает под курсором или фокусом; параллельно озвучивается через `aria-live` (ошибки — `assertive`).
**Приёмка:** клавиатурой можно найти товар, открыть просмотр, добавить, закрыть Escape и оказаться на исходной карточке.
**Зависимости:** WP1, WP2, WP4.

### WP6 — Корзина
**Цель:** корзина, которой можно доверять.
**Файлы:** `ui/cartView.js`, `ui/checkout.js`, `ui/infoView.js`.
**Сделано:** выдвижная панель из шапки; счётчик и сумма в шапке; строки с «+» / «−» (минус блокируется на 1, плюс — на остатке с пометкой «Максимум»); удаление и очистка с «Отменить»; промокод с сообщениями и «Убрать промокод»; итог «Товары / Скидка / К оплате»; пустое состояние с переходом в каталог; учебное «оформление» **без полей ввода** (подтверждение очищает корзину и показывает номер учебного заказа); информационные окна из подвала.
**Приёмка:** все числа в панели совпадают с `summarize()`; фокус после «+»/«−»/удаления остаётся на осмысленном элементе; панель закрывается Escape, фокус возвращается на «Корзина».
**Зависимости:** WP1, WP5.

### WP7 — «Собери экспедицию» и паспорт
**Цель:** главная фишка, доведённая до конца.
**Файлы:** `ui/expeditionView.js`, `ui/passport.js`.
**Сделано:**
- Шаги 1–3 (радио-карточки на нативных `input[type=radio]`, стрелки работают), шаг 4 — результат: описание, чипы «изменить», факты, список с чекбоксами «включить», итоги, «Добавить набор в корзину», «Паспорт экспедиции». Выбор сохраняется в `teamXX:expedition:v1` и при возврате назад.

- Паспорт — SVG-карточка из данных набора, одна и та же для показа в окне, печати и скачивания. Кнопки: PNG (через canvas), SVG, печать (`#print-root` + `@media print`). **Все три проверены в браузере**, поэтому показываются.
**Приёмка:** параметры меняют набор; исключение позиции пересчитывает итоги; при пустом наборе кнопки недоступны; PNG — валидный файл; в режиме печати виден только паспорт.
**Зависимости:** WP1, WP2, WP5, WP6.

## 6. Правила для агентов

1. Сначала прочитай этот файл, затем только нужный WP.
2. Контракты раздела 3 не менять. Нужна новая функция — добавляй, не ломая существующие.
3. Любую сумму получай из `summarize()` / `kitTotals()`. Не считай деньги в `ui/`.
4. Новая логика → сначала в `core/` с юнит-тестом, затем UI. Интерфейс проверяй вручную в браузере.
5. Данные из `localStorage` и любые внешние данные проходят через `sanitize.js`.
6. Никаких внешних CDN, шрифтов по ссылке, аналитики, ключей и `.env`. Всё нужное лежит в `site/`.
7. В HTML-строки подставляй текст только через `esc()` (`ui/dom.js`).
8. Диалоги — только через `setupDialog` / `openDialog`; уведомления — через `toast()` (озвучивание уже внутри).
9. Каждая анимация должна гаснуть при `prefers-reduced-motion`.
10. Обычные дизайнерские и технические решения принимай сам. Вопрос — только при существенном препятствии.
11. **Не утверждай, что проверка пройдена, если не запускал её.** Различай «проверено» и «написано, не проверено».

## 7. Принятые решения

| Вопрос | Решение |
|---|---|
| Фреймворк и сборщик | Нет: чистый JS (ES-модули), `site/` публикуется как есть |

| «Очистить корзину» | Очищает позиции, промокод остаётся |
| Отмена удаления | `reinstate`: возвращает только удалённые позиции, не откатывает остальные изменения |
| Паспорт | SVG-карточка; PNG, SVG и печать (все проверены) |
| Шрифты | Системные стеки, файлов шрифтов нет |
| Изображения | Собственные SVG, генерируются `tools/gen-images.mjs` |
| Оформление заказа | Учебное окно, без полей и без сбора данных |
| Номер команды | `TEAM_ID` в `site/js/config.js`, пока `team00` |
| Тесты | `node:test` для ядра и данных, pytest для API; браузерных автотестов нет |
| Бэкенд | FastAPI + uvicorn под systemd, без Docker; необязателен: при сбое сайт использует встроенный каталог (`core/apiCatalog.js`) |
| Источник каталога | `site/js/data/products.js` и `config.js`; `backend/app/catalog.json` генерируется `npm run export:catalog` |
